Time Awareness / Time Tracking
الفكرة

"أريد عادة جديدة."

بل نريد أن نبدأ بسؤال أعمق:

      ↓

      ↓

22. Prompt الخاص بـAI

نريد شيئًا مثل:

You are a supportive behavioral coach.

Analyze the user's tracked day.

Your job is NOT to judge the user.

Identify:
1. One meaningful pattern.
2. One potential opportunity for improvement.
3. A realistic small reduction if appropriate.
4. 3 replacement activities.
5. A short supportive explanation.

Never shame the user.
Never diagnose the user.
Do not claim that a habit is clinically harmful.
Do not invent information that is not present in the data.

Prefer small realistic changes.

Return structured JSON.

ثم JSON:

{
  "headline": "...",
  "observation": "...",
  "pattern": "...",
  "opportunity": "...",
  "suggested_change": {
    "minutes": 20,
    "category": "social_media"
  },
  "replacements": [
    {
      "title": "Read",
      "minutes": 20
    },
    {
      "title": "Walk",
      "minutes": 20
    }
  ]
}
23. إذا AI فشل

التجربة لا تتوقف.

نستخدم fallback.

مثلاً:

إذا:

social_media > 120 minutes

نعرض:

لاحظنا أن وسائل التواصل أخذت جزءًا كبيرًا من وقتك اليوم. قد تكون 15–20 دقيقة هدفًا مناسبًا لتجربة تغيير صغير.

ثم نعرض replacements ثابتة.

30. Prompt جاهز لـReplit لهذه الميزة

هذا هو النص الذي أعطيه للـAI Agent بعد أن نتفق على UX:

Implement the Time Awareness / Time Tracking feature according to the following product specification.

IMPORTANT:
Do not redesign unrelated pages.
Do not change the existing database architecture unless required.
Do not remove existing functionality.
Use the existing authentication and backend.

USER FLOW:

Dashboard
→ "Where did your day go?"
→ Start Tracking
→ Choose 15 or 30 minute interval
→ Tracking state
→ Check-in notification
→ User selects activity
→ Entry is saved
→ User can edit entries
→ User can pause/resume tracking
→ User finishes the day
→ Day summary
→ Timeline
→ Category totals
→ AI insight
→ Suggested small reduction
→ Replacement activities
→ "Start a habit" CTA

UX REQUIREMENTS:

1. Default interval = 15 minutes.
2. User can switch to 30 minutes.
3. User can pause tracking at any time.
4. User can resume tracking.
5. Check-ins must be extremely fast.
6. Do not require typing for normal check-ins.
7. Provide predefined categories:
   Study, Work, Social Media, Gaming, Entertainment,
   Exercise, Eating, Rest, Travel, Socializing, Personal, Other.
8. Provide "I don't remember" option.
9. Allow editing an entry.
10. Show daily timeline.
11. Show total tracked time.
12. Show category totals.
13. Show percentages.
14. Show top categories.
15. Show useful time patterns when enough data exists.
16. Do not shame the user.
17. If there is insufficient data, do not invent insights.

AI:

Create a server-side AI analysis function.

The application calculates:
- total tracked minutes
- category totals
- percentages
- time blocks
- top categories

Send these structured facts to the AI.

The AI returns:
- headline
- observation
- pattern
- opportunity
- suggested reduction
- replacement activities

Use structured JSON output.

Do NOT allow the AI to calculate authoritative application state.

If AI fails:
- use a deterministic fallback
- never break the user experience

The AI should be supportive, non-judgmental, concise, and should suggest small realistic changes.

After the AI recommendation, allow the user to:
- accept the suggestion
- reject it
- choose another replacement
- create their own habit

IMPLEMENT ALL UI STATES:
- empty
- tracking
- paused
- check-in
- editing
- loading
- AI loading
- AI success
- AI failure
- insufficient data
- completed analysis
- error

Before coding, inspect the existing project and report which existing components, API routes, and database tables can be reused.

Then implement the feature without breaking the current application.
