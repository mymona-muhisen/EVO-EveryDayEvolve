60. Prompt جاهز لـReplit
Implement Feature 06:
CHARACTER + XP + COINS + SHOP

IMPORTANT:
Do not redesign unrelated features.
Do not remove existing Journey, Habit Engine, AI Coach, Reward, or authentication functionality.
Inspect the current implementation first.
Reuse existing character assets and components if available.
If character/map assets already exist in the project, use them instead of creating replacements.

==================================================
1. PRODUCT GOAL
==================================================

The character system should reinforce the habit loop:

Complete habit
→ earn XP + Coins
→ progress character
→ unlock/buy items
→ customize character
→ same character appears on Journey

The character is NOT a separate game.

==================================================
2. XP VS COINS
==================================================

XP:
- represents overall user progression
- used for level calculation
- cannot be spent
- persists across journeys

Coins:
- virtual currency
- shared across all user journeys
- earned through successful habit completion
- spent on character items

Do not reset XP or Coins when a journey ends.

A missed habit does NOT remove XP or Coins.
It only means no reward is earned for that missed completion.

==================================================
3. COMPLETION REWARDS
==================================================

Use deterministic config.

Example:

Minimum successful completion:
+10 XP
+5 Coins

Full target completion:
+20 XP
+10 Coins

Adjust values if the existing project already defines a consistent reward system.

Do not hard-code reward values in multiple frontend components.

Centralize reward configuration.

The backend must be the authority for granting rewards.

==================================================
4. IDEMPOTENCY
==================================================

Completing the same habit day twice must NOT:
- award XP twice
- award coins twice
- advance the journey twice

Implement server-side idempotency / completion checks.

==================================================
5. CHARACTER
==================================================

Use one global character per user.

The same character appears:
- Profile
- Dashboard widget
- Journey map

Character customization is global.

If user has multiple journeys:
- use same character/outfit
- character position changes depending on the journey currently viewed

Do NOT create a separate character per habit.

==================================================
6. CHARACTER CUSTOMIZATION
==================================================

Support current available assets.

Preferred layer structure:

Base
Hair
Top
Bottom
Hat
Accessory
Special

If current assets are not separated into layers, support the existing asset structure without blocking V1.

Keep V1 small:
- a few tops
- a few hats
- a few accessories

Do not create a huge character creator.

==================================================
7. CHARACTER PAGE
==================================================

Create/update Character page.

Show:

- large character preview
- Level
- XP progress
- Coin balance
- Customize controls

Example:

My Character

Level 4
340 / 450 XP

Coins: 120

[ Customize ]

Wardrobe:

Character preview updates immediately after equip.

==================================================
8. XP LEVEL SYSTEM
==================================================

Create deterministic functions:

getLevelFromXP(xp)
getXpForNextLevel(level)
getLevelProgress(xp)

Use one centralized configuration or formula.

Do not calculate level separately in different components.

When user reaches a new level:
- show small celebration
- optionally unlock a milestone item

XP never decreases.

==================================================
9. COIN WALLET
==================================================

Use existing wallet implementation if present.

Support:
- balance

- spending transaction

Preferred transaction sources:
- habit_completion

Store transaction metadata such as:
- amount

Do not allow frontend to directly set coin balance.

11. PURCHASE FLOW
==================================================

When user clicks Buy:

- Buy
- Cancel

Backend must verify:

- user is authenticated
- user has enough coins
- user does not already own item

Perform purchase transactionally:
- subtract coins
- add inventory item

Do not trust client-provided price.

Prevent duplicate purchases from double clicks.

==================================================

==================================================

Use:

- user_id

==================================================

- Journey
