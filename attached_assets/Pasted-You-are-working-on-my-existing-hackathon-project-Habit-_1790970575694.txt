# PROJECT CONTEXT

Habit Journey is an Arabic RTL habit-improvement website for teenagers and older.

The core product philosophy is:

Observe → Understand → Suggest → Adapt → Act → Recover → Evolve

The app should feel like it understands the user instead of forcing them to manually explain everything.

The project already contains:

* Arabic RTL frontend
* Authentication
* Database
* Habit tracking
* Daily check-ins
* Time tracking
* Dashboard
* Journey / map
* Character
* Rewards / virtual currency
* Memories
* AI integration with fallback behavior
* Streak / XP / recovery logic

The current problem is that Time Tracking and AI Analysis exist, but they do not yet form a strong intelligent loop.

I want you to implement the following connected experience.

08 — FALLBACK LOGIC
===================

AI failures must never break the page.

Implement deterministic fallback logic based on the same structured analytics.

Examples:

If one category dominates the day:
→ suggest recovering a small number of minutes.

If a habit has low completion for multiple days:
→ suggest reducing target.

If a habit has high completion:
→ suggest gradual increase.

If the data is insufficient:
→ show "نحتاج إلى مزيد من الأيام لاكتشاف نمط واضح."

Use fallback Arabic wording.

The frontend must not depend on AI being available.
