هذه الميزة يجب ألا تجعل Habit Journey شبكة اجتماعية جديدة؛ الهدف منها هو إضافة شيء واحد مهم:

"أنا لا أخوض رحلة تطوير نفسي وحدي."

والحلقة الاجتماعية تكون:

Friend / Group
      ↓
Shared Goal or Visible Progress
      ↓
Encouragement
      ↓
More motivation to continue
      ↓
Habit completion
      ↓
New progress to share

والقاعدة الأهم:

المستخدم يشارك تقدمه الذي يختاره، وليس حياته كلها.

خصوصًا أن المنتج يمكن أن يستخدمه مراهقون، لذلك الخصوصية والسلامة يجب أن تكون جزءًا من التصميم منذ البداية.

58. Prompt جاهز لـReplit
Implement Feature 09:
FRIENDS / GROUPS / ENCOURAGEMENT / SHARED JOURNEYS

IMPORTANT:
Do not redesign unrelated features.
Do not remove Habit, Adaptive Engine, Daily Experience, Journey, Map, Character, XP, Coins, Reward, or Memories.
Inspect existing group/social APIs and database tables first.
Reuse current implementation where possible.

The goal is to add a lightweight social layer, NOT a full social network.

==================================================
1. PRODUCT PRINCIPLE
==================================================

The social experience should communicate:

"You don't have to do this alone."

Users can:
- connect with friends
- share selected progress
- encourage each other
- optionally participate in shared challenges

Do NOT create a generic social media feed.

==================================================
2. FRIENDS
==================================================

Implement:

- search users by username
- send friend request
- accept
- decline
- remove friend
- block user
- friends list
- friend profile

Friend profile may show ONLY information the user has explicitly shared.

Default private:
- time tracking
- detailed habits
- missed reasons
- rewards
- private Memories

==================================================
3. FRIEND PROFILE
==================================================

Show when permitted:

- character
- visible active journey
- journey progress
- consistency
- achievements
- shared Memories

Do not expose:
- detailed time logs
- private habits
- failure reasons
- exact personal data
- precise location

==================================================
4. VISIBILITY
==================================================

Support:
- private
- friends
- selected users

Public visibility may be deferred if needed.

Privacy defaults to PRIVATE.

Do not auto-share anything.

==================================================
5. ENCOURAGEMENT
==================================================

Add lightweight one-click encouragement.

When a friend completes a habit or milestone:

Show:
"Sarah completed Day 8"

Button:
"Encourage"

Options:
- 🎉 Nice work!
- 🔥 Keep going!
- 👏 Great job!
- 💪 You got this!
- ✨ Keep moving!

Also allow a short custom message if current architecture supports it.

Do NOT build direct messaging.

Do NOT call AI for ordinary encouragement.

Avoid excessive notifications/spam.

==================================================
6. ENCOURAGEMENT DATA
==================================================

Use/reuse an encouragement entity:

id
sender_id
receiver_id
journey_id
type
message
created_at

Verify sender and receiver permissions server-side.

==================================================
7. SHARED CHALLENGE
==================================================

22 days

Minimum 5 min

Minimum 5 min

Each user keeps:
- own target
- own minimum
- own difficulty
- own consistency
- own journey

Allow selecting existing friends.

Create shared challenge.

Invite users.

Recipients can:
- Join

Do not automatically create a habit without acceptance.

18. AI
==================================================

AI is NOT required for this social feature.

Use templates for encouragement.

==================================================
19. DATA SECURITY
==================================================

Server-side permission checks must control:
- friend requests
- friendships
- profile visibility
- journey visibility
- challenge membership
- group membership
- encouragement
- Memories visibility

Never trust client-supplied user IDs for authorization.

A user must not be able to read another user's private journey by changing an ID in the request.

20. RATE LIMITING / SPAM
==================================================

Prevent encouragement spam.

A basic server-side rate limit is sufficient.

Do not allow unlimited repeated encouragement to the same user in seconds.
