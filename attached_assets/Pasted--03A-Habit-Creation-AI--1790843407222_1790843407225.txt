==================================================
PART B — HABIT EXECUTION
==================================================

Habit page must display:

- today's target

- today's progress
- journey day
- consistency
- reward
- completion CTA

For BUILD habits:
- actual >= minimum = successful day
- actual >= target = target completed

For REDUCE habits:
- actual <= success limit = successful day
- actual <= target limit = target achieved

Do not label a minimum-achieved day as a failure.

PART D — MISSED DAY
==================================================

When user misses a habit, ask:

🕐 No time

⚡ Unexpected event
✍️ Other

Save reason.

Do not reset the journey.

==================================================
PART E — ADAPTIVE RULE ENGINE
==================================================

Implement deterministic rules.

BUILD HABITS:

- one difficult day alone must not trigger a major change
- repeated Hard/Very Hard results should reduce the future target
- repeated Easy results may trigger a small increase suggestion
- Normal results should generally keep the current target
- Too difficult -> reduce future target/minimum
- No time -> provide Busy Day Version instead of automatically lowering the standard target
- Forgot -> suggest a cue/reminder adjustment
- Lost motivation -> simplify the starting action
- Unexpected event -> normally keep the plan

REDUCE HABITS:

- repeated successful reductions may gradually lower the limit
- repeated difficulty should slow the reduction rate
- do not force aggressive reductions
- preserve a user-editable target

Target changes must be gradual.

Never:
- reset the whole journey because of one miss
- dramatically increase the target after a few easy days
- decrease the minimum forever
- allow the LLM to directly modify numeric values

==================================================
PART F — ADAPTATION + AI
==================================================

Architecture:

User data
→ deterministic rules
→ recommended adjustment
→ AI explanation
→ UI

Create:

adaptHabit()

Input:
- current target
- current minimum/limit
- recent completion
- difficulty history
- missed-day reasons

Output from deterministic engine:
- action
- new target
- new minimum/limit
- reason

Then call AI only to explain the adjustment naturally in Arabic.

AI must NOT change the numbers.

==================================================

Support a smaller fallback action.

Example:

Minimum = 5 min
Busy-day version = 3 min

This should be used when the user reports:
"No time"

Do not automatically destroy the main habit target.

The database must preserve all values independently.
