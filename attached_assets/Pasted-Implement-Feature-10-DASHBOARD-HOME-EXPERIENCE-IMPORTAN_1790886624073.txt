Implement Feature 10:
DASHBOARD + HOME EXPERIENCE

IMPORTANT:
Do not redesign the entire application.
Do not remove existing features.
Do not rebuild working functionality from scratch.

First inspect:
- current Dashboard
- current profile API
- current habit APIs
- current journey API
- current reward API
- current character/wallet API
- current time tracking API
- current AI/day analysis implementation
- existing navigation

Reuse existing components and APIs wherever possible.

==================================================
PRODUCT GOAL
==================================================

The Dashboard is the user's intelligent daily home.

It should answer immediately:

1. What is happening today?
2. What should I do now?
3. How am I progressing?
4. What am I working toward?

It must NOT become a dense analytics page.

The primary experience is:
TODAY'S ACTION → PROGRESS → AI INSIGHT → JOURNEY → REWARD

==================================================
1. STATE-AWARE DASHBOARD
==================================================

Dashboard content and primary CTA must adapt to the user's state.

STATE A:
New user / no tracking:
Show:
- greeting
- "Let's understand your day"
- Start Tracking CTA

STATE B:
Tracking active:
Show:
- tracked time
- tracking status
- next check-in
- Pause/Resume

STATE C:
Day analysis available:
Show:
- top time insight
- AI Coach card
- current habit

STATE D:
Habit not started:
Primary CTA:
Start today's habit

STATE E:
Habit in progress:
Primary CTA:
Continue today's habit

STATE F:
Minimum reached:
Show:
Minimum reached
Continue / Finish for today

STATE G:
Target completed:
Show:
Target complete
Journey progress
XP/Coins feedback

STATE H:
Missed previous day:
Show missed-day reflection first
Ask why
Allow adaptation flow

STATE I:
Journey completed:
Show:
Journey complete
Reward unlocked
Character celebration
Start another journey

3. GREETING
==================================================

==================================================
4. HERO / YOUR DAY
==================================================

If no tracking:
"Let's see where your day goes."

If tracking:
Show:
- tracked minutes
- interval
- active/paused state
- next check-in

If day analysis exists:
Show concise time insight.

Do not duplicate the entire Time page.

CTA should adapt to current state.

==================================================
5. TODAY'S FOCUS
==================================================

This is the primary habit card.

Show:
- habit name
- target
- minimum
- actual progress
- progress bar
- journey day
- consistency

Primary action:
- Start
- Continue
- Complete
depending on state

Minimum must be clearly visible.

Example:
Target: 10 min
Minimum: 5 min

Explain:
"Even on a difficult day, the minimum keeps your journey moving."

==================================================
6. MULTIPLE HABITS
==================================================

If user has several active habits:
show ONE primary "Today's Focus" habit.

Then show a compact list of other habits.

Do NOT show multiple large habit cards.

Preferred priority:
1. active/incomplete priority habit
2. earliest relevant habit
3. incomplete habit requiring action

Keep logic deterministic.

==================================================
7. JOURNEY PREVIEW
==================================================

Do not render the full map on Dashboard.

Show a compact Journey Preview:

- habit
- current day / 22
- small visual route
- character position
- consistency

CTA:
"Open Journey"

Journey details remain on the Journey page.

==================================================
8. REWARD PREVIEW
==================================================

Show:
- reward title
- optional image
- journey day
- days remaining
- simple progress bar

Do not confuse:
journey day
consistency
reward progress

Do not implement payment.

==================================================
9. CHARACTER WIDGET
==================================================

- level
- XP progress
- coin balance

"Customize"

Do not duplicate the entire Character page.

Use the same character state/appearance as Journey.

==================================================
10. AI COACH CARD
==================================================

Do NOT create a generic chatbot.

Show an inline contextual card:

"Your Coach"

Example:
"لاحظت أن معظم وقت وسائل التواصل لديك يتركز بين 8 و11 مساءً."

Then:
"قد تكون استعادة 20 دقيقة فرصة جيدة لتجربة تغيير صغير."

Actions:
- جرّب هذا التغيير
- ليس الآن

The AI card should use the latest cached day analysis.

Do NOT call Gemini on every Dashboard load.

If no useful insight:
show a calm message such as:
"لا توجد ملاحظة كبيرة اليوم."

Do not invent insights.

13. MEMORY WIDGET
==================================================

If a Memory exists for today:
show a small memory card.

If no Memory:
do not create a large empty card.

Memory is optional and must never be treated as proof.

14. NAVIGATION
==================================================

==================================================
15. DASHBOARD DATA API
==================================================

Prefer an existing consolidated:
GET /api/dashboard

Return the data required by Dashboard when practical:

- profile
- active/priority habit
- today's habit day
- today's progress
- consistency
- active journey
- journey progress
- reward
- character
- XP
- coins
- compact time summary
- latest cached AI insight
- compact friend data
- today's memory if available

Do not trigger AI from dashboard API.

Do not create multiple redundant requests if a consolidated endpoint already exists or can safely be extended.

==================================================
16. AI CACHE
==================================================

Dashboard must NOT call AI on every refresh.

Use latest stored/cached day analysis.

If analysis is stale:
show existing result and an appropriate action such as:
"Refresh today's insight"

Do not automatically call Gemini just because the dashboard opened.

==================================================
17. PARTIAL FAILURE
==================================================

Dashboard should continue working if a secondary service fails.

Examples:

AI fails:
show fallback Coach message.

Friends fails:
hide social content or show retry.

Memory fails:
do not break habit.

Time summary fails:
show compact retry state.

Do not let one feature break the whole dashboard.

==================================================
18. NEW USER
==================================================

New user should not see empty cards everywhere.

Instead show a guided first state:

1. Understand your day
2. Track a small part of your day
3. Get your first insight
4. Create your first habit

Primary CTA:
"Start tracking"
