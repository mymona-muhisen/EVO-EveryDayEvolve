Implement Feature 08:
MEMORIES 📸

IMPORTANT:
Do not redesign unrelated features.
Do not remove Habit, Daily Experience, Journey, Character, XP, Coins, or Reward functionality.
Inspect the existing image storage and memory implementation first.
Reuse the existing storage/API/components wherever possible.

==================================================
1. PRODUCT GOAL
==================================================

A Memory is an optional photo attached to a specific completed habit day.

It should transform progress into something the user can remember later.

Concept:
Habit completion
→ optional Memory
→ attach to Journey Day
→ show on map
→ view later
→ optionally share in future social features

Memory is NOT proof of habit completion.

The habit can be completed without a Memory.

==================================================
2. ENTRY POINT
==================================================

After successful habit completion, show:

"Capture this moment"

Options:
- Add Memory
- Maybe later

Do not force a photo.

Do not make the user upload a photo before completion.

==================================================
3. ADD MEMORY
==================================================

Allow:
- take photo where browser/device supports it
- choose image from gallery/file picker

Supported:
- JPG/JPEG
- PNG
- WebP

Add:
- image preview
- optional caption

Caption placeholder:
"What do you want to remember?"

Keep caption short.

==================================================
4. MEMORY DATA
==================================================

Reuse existing memories table if available.

Preferred:

id
user_id
journey_id
habit_day_id
image_url
thumbnail_url if supported
caption
visibility
created_at
updated_at

Relationship:

User
→ Journey
→ Habit Day
→ Memory

One Memory per Habit Day in V1.

==================================================
5. PRIVACY
==================================================

Private by default.

Do not expose Memories publicly by default.

If social functionality already exists, support:
- private
- friends
- selected users
- public

If social is not yet implemented, keep the model extensible but only activate private behavior.

A user must only be able to access their own private memories.

==================================================
6. MAP INTEGRATION
==================================================

If a Habit Day has a Memory:
show a small memory indicator/thumbnail on its Journey node.

Do not place full-size images all over the map.

On clicking the memory indicator:
open Memory detail.

Memory detail shows:
- Day
- Habit
- image
- caption
- difficulty if available
- journey context

==================================================
7. MEMORY GALLERY
==================================================

Add a simple Memories section to Profile or the existing journey/profile area.

Grid:
- image
- day number
- habit/journey context

Click:
open detail.

Do not build a social photo feed.

==================================================
8. EDIT / DELETE
==================================================

Allow:
- edit caption
- delete memory

Delete confirmation required.

Deleting a Memory must NOT:
- undo habit completion
- remove coins
- remove XP
- move journey backwards

It only removes the Memory.

==================================================

==================================================

Reuse the existing image storage service.

If possible:
- optimize/compress image
- restrict maximum file size
- generate thumbnail where practical

Never use the original filename as a security identifier.

Use a unique server-generated identifier.
